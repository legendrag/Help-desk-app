# Internationalization (i18n)

How English/Arabic localization works in mlamehticket and how to maintain catalogs without GNU gettext binaries.

**Audience:** Developers adding UI strings or shipping Arabic translations.

## Runtime behavior

| Setting | Value |
|---|---|
| `LANGUAGE_CODE` | `en` |
| `LANGUAGES` | English (`en`), Arabic (`ar`) |
| `LOCALE_PATHS` | project `locale/` |
| Catalogs today | **`locale/ar` only** (English is the source language) |
| Language selection | Cookie `django_language` via Django’s `i18n` URLs + `LocaleMiddleware` |

There are **no** language-prefixed URL paths (`/ar/...`). The same named routes serve both languages; HTMX endpoints need no special language routing.

`USE_I18N = True`. Templates should use `{% load i18n %}` and Django translation tags/filters; Python should use `gettext` / `gettext_lazy` / `gettext_noop` as appropriate.

## Tooling: `scripts/i18n.py`

Pure-Python stand-in for `makemessages` / `compilemessages`. **GNU gettext (`xgettext`, `msgfmt`) is not required.**

Dependency: **`polib`** from `requirements-dev.txt`.

```bash
pip install -r requirements-dev.txt

python scripts/i18n.py extract          # report extractable messages
python scripts/i18n.py update           # merge into locale/ar/.../django.po (keeps msgstr)
python scripts/i18n.py compile          # write django.mo
python scripts/i18n.py check --verbose  # exit 1 on missing/untranslated
```

Useful flags:

- `extract --list` — print every message
- `check --verbose` — list offending strings
- `--quiet` — suppress extraction stats where supported

`test-local.ps1` runs `check` as part of the local gate. Run **`update` + `compile`** whenever you add or reword a `{% trans %}`, `{% blocktrans %}`, or `_()` / `gettext_*` string. Missing translations fail silently at runtime (English msgid renders).

## Template rules

### Always use `trimmed` on `blocktrans`

```django
{% blocktrans trimmed with name=user.username %}Hi, {{ name }}{% endblocktrans %}
```

Without `trimmed`, surrounding newlines and indentation become part of the msgid and Arabic lookup fails quietly.

### Prefer explicit translation APIs

- Short strings: `{% trans "…" %}` or `_(…)` / `gettext_lazy`
- Strings with variables or HTML structure: `{% blocktrans trimmed … %}`
- Deferred notification copy: `gettext_noop` at definition, translate later (see notifications bilingual helpers)

## Python extraction notes

The script walks project Python (skipping migrations, venv, staticfiles, media, etc.) via `ast`, and templates via Django’s `templatize()` plus a literal scanner. It understands singular/plural/context gettext helpers and `gettext_noop`.

Some strings are allowlisted as intentionally untranslated (for example `TLS`, `SSL`, example email addresses).

## Workflow checklist

1. Add or change the English source string in template/Python.
2. `python scripts/i18n.py update`
3. Translate new empty `msgstr` entries in `locale/ar/LC_MESSAGES/django.po`
4. `python scripts/i18n.py compile`
5. `python scripts/i18n.py check --verbose`
6. Spot-check UI with Arabic selected (cookie / language form)
